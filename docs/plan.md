## 2. 기획 배경 및 의도

### 문제 인식

고령화 사회로의 전환이 가속화되면서 요양시설 내 인력 부족 문제가 심화되고 있다. 요양보호사는 하루에도 수십 번 발생하는 단순 반복 요청(물 전달, 물품 수거 등)에 시간을 빼앗겨 핵심 케어에 집중하지 못하고 있으며, 바닥에 방치된 물품으로 인한 낙상 사고 위험도 증가하고 있다.

| 문제 | 영향 |
|------|------|
| 반복 심부름(물 전달, 물품 수거 등) | 요양보호사 핵심 케어 시간 감소 |
| 버튼 중심 UI의 명령 표현 한계 | 상황별 세밀한 지시 불가 |
| 바닥 방치물, 장애물 | 낙상 위험 증가 |
| 복잡한 경로에서의 주행 불안정 | 로봇 운용 신뢰성 저하 |
| 원격 로봇 상태 파악 어려움 | 운영자 대응 지연 |
| 오류 로그 수동 분석 부담 | 유지보수 비효율 |

### 핵심 컨셉

- **LLM 기반 자연어 명령 해석**: 복잡한 명령어 없이 음성 또는 텍스트로 로봇에게 작업 지시
- **Digital Twin 기반 실시간 모니터링**: 로봇 상태를 웹 맵에 실시간 동기화하여 운영 효율화
- **자율 주행 + Pick & Place**: 딥러닝 기반 정밀 주행 및 로봇팔을 통한 물품 처리

## 3. 서비스 개요

### 서비스명

**보미** (요양보호사의 든든한 AI 로봇 동료)

### 서비스 대상

- 요양원 및 실버케어 시설
- 요양보호사 (직접 사용자)
- 시설 운영자 (관제 대시보드 사용자)
- 입실자 및 보호자 (Telegram WebApp 알림 수신)

### 주요 목표

| 목표 | 내용 |
|------|------|
| **사용자 편의성** | 터치, 텍스트, 음성 3가지 입력 방식으로 로봇 지시 |
| **안전 강화** | YOLOv5s로 바닥 장애물 감지 → 즉시 정지, 로봇팔로 직접 정리 |
| **관리 효율화** | Digital Twin + LLM 운영 브리핑으로 현장 상황 실시간 파악 |

## 4. 기능 목록

### 핵심 기능

| 기능 | 설명 |
|------|------|
| **멀티모달 명령 입력** | 터치, 텍스트, 음성(Whisper STT) → GPT-4.1 nano가 의도 파악 후 태스크 생성 |
| **자율 주행** | ResNet-18 라인 트레이싱, 곡선·교차로·180° 정밀 회전 구현 |
| **Pick & Place** | YOLOv5s TFLite로 물체(컵·인형·블록) 인식 → 로봇팔로 파지, 전달, 정리 |
| **온디맨드 리소스 최적화** | 주행 중 웹캠 OFF(ResNet-18만 동작), 작업 시 웹캠 ON(YOLOv5s 활성화) |
| **Digital Twin** | MQTT로 로봇 위치·상태를 Vue3 웹 맵에 0.1초 단위 실시간 동기화 |
| **LLM 운영 브리핑** | GPT-5가 Firestore 로그 분석 → 이상 징후, 원인 후보, 조치 순서 제안 |
| **실시간 모니터링** | 배터리 전압, 적재 여부, 센서 데이터, 에러 로그 실시간 그래프 시각화 |
| **원격 제어** | 웹 대시보드에서 비상 시 수동 개입 |
| **Telegram WebApp 알림** | 작업 진행 상황, 장애물 감지 등 실시간 알림 |
| **루틴 스케줄러** | 시간 기반 반복 태스크 자동 실행 (Node-RED) |

### 동작 시나리오

| 단계 | 동작 | 기술 |
|------|------|------|
| **① 명령 수신** | 버튼, 텍스트, 음성으로 작업 요청 | Whisper(STT) + GPT-4.1 nano |
| **② 경로 주행** | 디지털 트윈 기반 최적 경로 주행 | ResNet-18, 조향 regression |
| **③ Pick & Place** | 목적지 도착 후 객체 인식 및 로봇팔 제어 | YOLOv5s TFLite |
| **④ 실시간 보고** | 작업 진행 상황 즉시 전달 | Telegram Bot API, MQTT |

## 5. AI 기능 명세

### AI 기능 ① — LLM 기반 자연어 명령 해석

사용자의 음성 또는 텍스트 입력을 구조화된 태스크(JSON)로 변환한다.

**입력 예시:**
```
"Room A에 물 가져다줘"
"지금 2호실 물건 좀 정리해"
```

**출력 예시:**
```json
{ "type": "deliver_water", "destination": "Room_A" }
```

- 모델: GPT-4.1 nano (GMS 프록시)
- 음성 입력: Whisper STT → 텍스트 추출 후 동일 파이프라인 처리
- 잘못된 명령은 LLM이 보정(Validation) 후 응답

---

### AI 기능 ② — Vision 기반 물체 인식 (YOLOv5s TFLite)

주행 중 또는 목적지 도착 후 카메라로 물체를 감지하여 Pick & Place 작업에 활용한다.

| 항목 | 내용 |
|------|------|
| 모델 | YOLOv5s TFLite (`best-fp16.tflite`) |
| 클래스 | Cup(0), Doll(1), Block(2) |
| 입력 | USB 웹캠 (작업 모드 시 활성화) |
| 출력 | 바운딩 박스, 클래스, 신뢰도 |
| 임계값 | confidence 0.35, NMS IoU 0.45 |

---

### AI 기능 ③ — ResNet-18 라인 트레이싱

라인을 따라 자율 주행하는 딥러닝 기반 조향 제어 모델.

| 항목 | 내용 |
|------|------|
| 모델 | ResNet-18 (조향 regression) |
| 입력 | CSI 카메라 (주행 모드 시 상시 동작) |
| 출력 | 조향값 (steering angle) |
| 특징 | 곡선, 교차로, 180° 회전 지원 |

---

### AI 기능 ④ — LLM 운영 브리핑 (GPT-5)

Firestore에 쌓인 interaction·task·event 로그를 GPT-5가 분석하여 운영 인사이트를 제공한다.

**출력 예시:**
```
이번 주 총 42건의 작업 중 Room_A 물 전달 요청이 가장 많았습니다.
오전 10~11시에 요청이 집중되어 해당 시간대 루틴 설정을 권장합니다.
```

- 이상 징후, 원인 후보, 우선순위별 조치 제안 포함
- 캐시 TTL: 3분 (동일 기간 중복 호출 방지)

## 6. 시스템 아키텍처

```
         NVIDIA Jetson Nano (AGV)              Raspberry Pi 5 (HMI)
  ┌─────────────────────────────────┐     ┌──────────────────────────────┐
  │  ResNet-18     YOLOv5s TFLite  │     │  PySide6 Qt GUI              │
  │  라인 트레이싱   객체 인식       │     │  터치 / 텍스트 / 음성 명령   │
  │  [주행] 웹캠 OFF                │     │  Whisper STT → GPT 의도 파악 │
  │  [작업] 웹캠 ON + 로봇팔        │     │  실시간 상태 / 로그 시각화   │
  └─────────────────────────────────┘     └──────────────────────────────┘
              │  MQTT pub                             │  MQTT sub/pub
              └─────────────────┬─────────────────────┘
                                ▼
              ┌────────────────────────────────────────┐
              │              Node-RED Server            │
              │   MQTT 수신, 태스크 분기, REST API 정의  │
              │   Firebase 상태 관리, LLM 호출           │
              └──────────┬──────────────┬──────────────┘
                         │              │
            REST / WS    │              │  Firestore SDK
                         ▼              ▼
            ┌────────────────┐   ┌──────────────────┐
            │  Web Dashboard │   │  Firebase DB      │
            │  Vue 3 + Vite  │   │  robots / tasks   │
            │  실시간 관제 맵 │   │  events / inter.. │
            └────────────────┘   └──────────────────┘
                                        Telegram WebApp
                                        실시간 진행 알림
```

### 사용자 채널별 역할

| 채널 | 사용자 | 주요 기능 |
|------|--------|-----------|
| Raspberry Pi Qt HMI | 현장 요양보호사 | 터치/텍스트/음성 명령, 상태 확인, 수동 제어 |
| Web Dashboard (Vue3) | 시설 운영자 | 실시간 관제 맵, 태스크 관리, 로그/통계 |
| Telegram WebApp | 요양보호사, 보호자 | 작업 진행 알림, 원터치 명령 |

## 8. 데이터 모델

Firebase Firestore 컬렉션 구조:

| 컬렉션 | 주요 필드 | 용도 |
|--------|-----------|------|
| `robots` | robot_id, state, battery, pose, updated_at | 로봇 상태 실시간 동기화 |
| `tasks` | task_id, type, destination, status, robot_id | 태스크 이력 관리 |
| `events` | event_id, robot_id, type, detail, ts | 장애물 감지, 태스크 완료 등 이벤트 로그 |
| `interactions` | interaction_id, source, input_mode, raw_input, parsed_type, result | 사용자 명령 이력 (LLM 분석용) |

## 10. 기획 변경 이력

### v1.0 — 초기 기획 (2025.12.10)

**서비스명:** Smart Twin AGV Home Assistant

**개요:** 2대의 AGV가 협력하여 1인 가구 또는 바쁜 직장인의 집안일을 자동 수행하는 개인 비서 서비스

| 계획 기능 | 내용 |
|-----------|------|
| Twin AGV 협력 스케줄링 | 2대가 충돌 없이 태스크 분배 |
| LLM 자연어 명령 | 고수준 Task JSON 변환 |
| 빨래 분류 | Vision 기반 세탁물 인식 및 수거 |
| 홈 IoT 연동 | 기상/외출 스케줄 기반 자동 기동 |
| 활동 요약 리포트 | 하루 AGV 작업 LLM 요약 |

| 핵심 시나리오 | 빨래 분류, 일정 기반 집안일 | 물 전달, 물품 수거, 낙상 방지 |

| AI 분석 | 일일 활동 요약 | Firestore 로그 기반 LLM 운영 브리핑 |
| 서비스명 | Smart Twin AGV Home Assistant | 보미 |
